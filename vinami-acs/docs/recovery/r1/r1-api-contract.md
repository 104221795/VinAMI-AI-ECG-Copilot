# R1 API Contract

Prefix: `/api/v1`. These endpoints persist real PostgreSQL state through application handlers.

| Method | Path | Result |
|---|---|---|
| POST | `/patients` | Register a non-sensitive Patient reference |
| GET | `/patients/{patient_id}` | Retrieve one Patient |
| POST | `/encounters` | Start an Encounter for an existing Patient |
| GET | `/encounters/{encounter_id}` | Retrieve one Encounter |
| POST | `/clinical-cases` | Open one suspected ACS Clinical Case |
| GET | `/clinical-cases` | List active cases with pagination and filters |
| GET | `/clinical-cases/{case_id}` | Retrieve one Clinical Case |
| GET | `/clinical-cases/{case_id}/timeline` | Retrieve persisted lifecycle timeline |
| GET | `/clinical-cases/{case_id}/audit` | Retrieve immutable lifecycle audit |

## Command headers

All POST operations require `X-Actor-ID`, `X-Actor-Role`, `X-Correlation-ID`,
`X-Request-Source`, and `Idempotency-Key`. Actor identity is structurally validated against a
persisted development identity record. It is not production-authenticated.

All responses include `X-Correlation-ID`. A missing GET correlation ID is generated by the API.

## DTO summary

`RegisterPatientRequest` contains `patient_reference` and an optional safe demographic summary
(`age_band`, `sex_at_birth`). R1 does not accept or return patient names or exact birth dates.

`StartEncounterRequest` contains Patient UUID, location, timezone-aware arrival timestamp, and an
optional synthetic external reference. `OpenClinicalCaseRequest` contains Encounter UUID, opening
reason, and typed operational priority.

Responses expose public UUIDs, aggregate version, UTC lifecycle timestamps, and context-owned
fields only. No ORM state or internal database metadata is returned. OpenAPI schema components
contain request-field and response examples.

## Listing

`GET /clinical-cases` accepts `page` (default 1), `page_size` (default 25, maximum 100), `status`,
`priority`, and `location`. Assigned-team filtering is not exposed because R1's existing Clinical
Case aggregate does not own an assignment. Results are ordered by `updated_at DESC, case_id DESC`.
An empty filtered page is distinct from a missing detail resource.

## Idempotency

Scope is `(actor_id, command_type, idempotency_key)`. Same key and same normalized payload returns
the stored original result, including after application restart. Same key with another payload
returns 409. PostgreSQL transaction advisory locking serializes concurrent duplicates. Aggregate,
idempotency result, and outbox rows commit together; failed commands store no successful result.

## Errors

Errors use `application/problem+json` with `type`, `title`, `status`, caller-safe `detail`,
`instance`, and `correlation_id`.

| Status | Meaning |
|---:|---|
| 400 | Missing/malformed command headers or domain command structure |
| 404 | Requested resource or required parent does not exist |
| 409 | Reference, active-case, idempotency, concurrency, or persistence conflict |
| 422 | Pydantic request/query validation failure |
| 500 | Unexpected persistence failure with internal detail suppressed |

## Projection consistency

POST responses confirm aggregate, idempotency, and outbox commit. Timeline and audit are projected
asynchronously by the internal worker and are therefore eventually consistent. The timeline/audit
GET endpoints never fabricate missing entries in memory.
