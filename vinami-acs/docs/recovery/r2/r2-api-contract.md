# R2 API Contract

All routes use `/api/v1`, verified identity dependencies, correlation IDs, RFC 7807 problem responses, and PostgreSQL-backed handlers. Commands require `Idempotency-Key`.

| Method | Path                                                                          | Permission     | Purpose                                      |
| ------ | ----------------------------------------------------------------------------- | -------------- | -------------------------------------------- |
| POST   | `/clinical-cases/{case_id}/triage-assessments`                                | `triage:write` | Record first triage revision                 |
| GET    | `/clinical-cases/{case_id}/triage`                                            | `triage:read`  | Read current triage revision                 |
| GET    | `/clinical-cases/{case_id}/triage/history`                                    | `triage:read`  | Read append-only triage history              |
| POST   | `/clinical-cases/{case_id}/triage-assessments/{assessment_id}/corrections`    | `triage:write` | Append triage correction                     |
| POST   | `/clinical-cases/{case_id}/vital-observation-sets`                            | `vitals:write` | Record a new observation set                 |
| GET    | `/clinical-cases/{case_id}/vitals`                                            | `vitals:read`  | Read repeated sets and revisions             |
| GET    | `/clinical-cases/{case_id}/vitals/latest`                                     | `vitals:read`  | Read latest sequence/revision                |
| POST   | `/clinical-cases/{case_id}/vital-observation-sets/{vital_set_id}/corrections` | `vitals:write` | Append vital-set correction                  |
| GET    | `/clinical-cases/{case_id}/triage-vitals-summary`                             | `triage:read`  | Read current records and completeness output |

## Concurrency and Idempotency

- New records require `expected_case_version`.
- Corrections require `expected_record_version` and must target the current revision.
- Reusing an idempotency key with the same payload returns the persisted response.
- Reusing the key with a different payload returns `409`.
- Stale expected versions return `409`.

## Error Semantics

`400` represents a domain invariant rejection, `401/403` identity and permission failures, `404` absent resources, `409` idempotency/concurrency/state conflicts, and `422` malformed request schema. Problem bodies retain the platform `type`, `title`, `status`, `detail`, `instance`, and `correlation_id` fields.
